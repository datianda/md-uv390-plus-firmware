# 16 MB 外部 SPI flash 分区图

依据 **实机整片备份** `backup/flash_full_16MB_20260920.bin`（不是读代码猜的）。
按 4 KB 扇区扫全 0xFF 得到：

| 区间 | 大小 | 内容 |
|---|---|---|
| `0x000000`–`0x223000` | 2.14 MB | 码表、校准、语音提示、卫星数据（中间有碎空洞） |
| `0x223000`–`0xE00000` | **11.86 MB** | **全空** |
| `0xE00000`–`0x1000000` | 2.00 MB | 频段日志 / GPS NMEA 日志（两者共用，只能开一个） |

实机上 `0xE00000` 起已写了 56 KB 频段日志，其余 1.95 MB 还空着。

## 新增：中文字库

    0x800000 – 0x900000    预留 1 MB
      0x800000  头 32 字节（独占一个 4 KB 扇区）
      0x801000  点阵数据

**为什么选 8 MB**：正好是芯片中点，往下离已用区顶端 `0x223000` 有 **5.86 MB**，
往上离频段日志 `0xE00000` 有 **5.00 MB**，两头都不可能撞上。而且 64 KB 块对齐、
是个记得住的整数。

**不能照抄 BA7IQE 的 `0xF80000`** —— 那是芯片最后 512 KB，**正落在我们频段日志的
2 MB 区里**。他要挤 GPS LOG（把 2M 缩到 1.5M）是因为他没别的地方放；我们有 11.86 MB
空白，没有任何理由去挤。

已验证：12x12 版 166,528 字节、13x13 版 180,064 字节，写进 `0x800000` 后
实机该区原本 **0 个非 0xFF 字节**，不会覆盖任何东西。

### 头（32 字节，小端）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u32 | magic `'CJKF'` = `0x464B4A43` |
| 4 | u8 | version = 1 |
| 5 | u8 | encoding，1 = GB2312 |
| 6 | u8 | width |
| 7 | u8 | height |
| 8 | u8 | bytesPerGlyph |
| 9 | u8 | 保留 |
| 10 | u16 | glyphCount = 6768 |
| 12 | u32 | dataOffset（相对区起点）= `0x1000` |
| 16 | u32 | dataLength |
| 20 | u32 | 点阵数据的 CRC32 |
| 24 | u32 | 生成时间 epoch |
| 28 | u32 | 保留 |

**有头这件事本身是对 BA7IQE 的改进**：他没有头，固件既分不清字库在不在、
也认不出版本 —— 字库没烧就满屏乱码。有了 magic，固件可以在开机时校一次，
没有就老老实实退回英文，不装作能显示中文。几何参数放头里还有个好处：
**换字号只要重生成再烧一次，固件不用重编**。

### 点阵排布

直接就是渲染器 `displayPrintCore()` 要的样子，读出来**不用任何解包**：

    byte = data[x + (y / 8) * width]      位 = (byte >> (y % 8)) & 1

每字 `width * ceil(height/8)` 字节，按字节对齐。

BA7IQE 把每字压到 16.5 字节（省 25%），代价是浮点乘 `charOffset * 16.5`、
读 17 字节、还要按 `charOffset % 2` 拆半字节相位 —— 约 40 行代码。
我们有 11.86 MB 空白，省那 27 KB 毫无意义，所以按字节对齐存，
固件侧 `SPI_Flash_read(base + off + slot * bytesPerGlyph, buf, bytesPerGlyph)` 一次读完。

### 索引

GB2312 双字节：`slot = (b0 - 0xB0) * 94 + (b1 - 0xA1)`，
`b0` 在 `[0xB0, 0xF7]`、`b1` 在 `[0xA1, 0xFE]`，共 72 x 94 = **6768 槽**。

`0xD7FA`–`0xD7FE` 那 5 个码位 GB2312 没有定义，**留空槽不压缩**。
BA7IQE 用 `if (b0 >= 0xd8) slot -= 5` 压掉了，省 5 个字（110 字节），
代价是多一个分支和一处差一错的风险 —— 不值。
生成时这 5 个槽会被自动识别（`6768 槽，其中 6763 个有点阵，5 个空槽`），
**这个数字本身就是一次自校验**。

## 工具

`tools/cjkfont.py`：

    build   从 TTF/TTC/BDF 生成字库（默认 12x12）
    show    把几个字打成 ASCII 点阵，肉眼校验位排布
    sheet   导出整本 6768 字的 PNG 大图
    flash   经 CPS 写进电台（复用 ogd77_write.py 的 FlashWriter）

**字库不进仓库，只进工具** —— 跟 AMBE codec 同样的处理。
理由见 F2：BA7IQE 的点阵表注释写着 *"Thank LoseHu provide compress chinese
character table"*，来源和授权都不清楚，而且那份 blob 本来也不在他的源码包里。

字体选择实测（**早先那版对照作废** —— 它是在"灰度渲染再切门限"上做的，
而那条路本身就在丢笔画，比出来的结论没有意义）：

| | 结论 |
|---|---|
| **simsun.ttc 14px 单色** | **在用**。宋体自带 12/14/16px 嵌入式点阵，单色模式下 FreeType 直接用那套手工字形 |
| simsun 12px 单色 | 笔画完整，但「频」「射」这类密字发挤。一行 12 字 |
| 灰度渲染 + 门限（任意字号） | **别用**。抗锯齿把 1px 横笔摊到两行、各约 50% 灰，两行都够不到门限，整条笔画消失 |

**两个坑，都是实机上看出来的：**

1. **别用"灰度渲染再切二值"** —— 用 `font.getmask(ch, mode="1")` 让 FreeType
   做单色 hinting。第一版满屏缺笔画（「用」少一横、「言」糊成一团）就是这个。
2. **字形的墨迹不是从第 0 行开始的** —— simsun 在 12px 和 14px 下墨迹都落在
   第 1 行到第 h 行，按 bbox 原样落位会把最后一行挤出格子：「电」变「申」、
   「卫」变「卩」、「主」丢顶点。工具现在**先量整本字库的墨迹范围再自动居中**，
   并逐字检查有没有笔画掉到格子外，通过了才出文件。

simhei / simsun 都是微软的字体，**只能自己用，不能随包分发**。
要做可分发版本用文泉驿点阵宋体（WenQuanYi Bitmap Song）的 BDF，工具直接吃。
