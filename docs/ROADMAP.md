# MD-UV390 / OpenGD77 改进路线

开始于 2026-09-21。源码基于官方 **R20260131**（fork: `dondch/OpenGD77-AES256`）。

## 硬约束：内存

两块 RAM 都快满了。**这是所有改动的前提**，先看这个再想功能。

```
RAM  (128K @0x20000000)   已用到 0x2001FFB0   剩   80 字节
CCM  ( 64K @0x10000000)   .ccmram = 0xff14    剩  236 字节
────────────────────────────────────────────────────────
合计剩余                                      约 316 字节
```

CCM 不是闲置的——校准数据、热点缓冲、声音表早占满了。

**推论：**
- 纯绘图改动（用已有的 40KB 帧缓冲）→ 不吃 RAM，随便做
- 新增全局变量 / 缓冲区 → 必须先腾地方
- 瀑布图就踩过一次：64 项调色板 LUT 占 128 字节 bss，直接把链接撑爆，改成实时计算才过

- [x] A5 **信道信息行 + 功率染色**（`ENABLE_INFO_DENSITY`）—— 已实机验收

      原计划里有两条查下来是错的，没做：
      - **「信道名大字号」上游早就有** —— `Display options → Text size` 就是
        `BIT_UI_USES_DOUBLE_HEIGHT`，用户本来就设成 2 了。
      - **「功率改色块」是拿事实换暗示** —— 换成色块就不知道是 1W 还是 5W 了。
        改成文字保留、按响度染色（最高档红、次两档琥珀）。

      真问题是量出来的：FM 信道屏 63% / DMR 46% 完全空白，最大空洞 y90–113（24 行），
      而**信道屏根本不显示频率**——信道就只是一个名字，
      「中继打不开」要查的三件事全藏在 SK1 或两层菜单后面。
      于是在那个洞里加一行紧凑信息，用次要文字色，不跟信道名抢。

      **自查揪出我自己两个设计错误**（第一版刷上去才发现的）：
      1. 打了 **RX 亚音**，该打 **TX 亚音** —— RX 只过滤你听到什么，
         TX 才是开中继的那个。AO-91 有 67.0 Hz 上行亚音却显示空白，
         正好在最该说话时哑了。改成优先 TX、没有才退回 RX，用 `T`/`R` 前缀标明。
      2. **跨波段显示差频没意义** —— AO-91 显示 `+289.290`，算术对但没用。
         差频 ≥10 MHz 时改为直接显示上行频率（10 MHz 能盖住所有业余中继差频，
         最宽的 70cm 是 7.6 MHz，不会误伤）。

      实机结果：
      ```
      DMR   145.3500 -0.600 CC8
      FM    438.5000                      （简易通信、无亚音）
      卫星  145.9600 >435.2500 T67.0      ← 下行 / 上行 / 上行亚音
      ```
      未实机跑过的组合：**普通差频 + 亚音**（本机没有这样的信道）。
      宽度算过：最宽 `145.9600 >435.2500 D023N` 24 字符 = 144px < 160。

      顺带发现：**DMR 表头里色码根本没画出来**（实测列段 `DMR`(1-17) `TS1`(28-43)
      `1W`(60-69)，中间空的），原因未查；这行里的 `CC8` 正好补上。

- [x] A6 **配色预设**（`ENABLE_THEME_PRESET`）—— 已实机验收，对比图 `backup/theme-mono-vs-colour.png`

      起因：`themeInitToDefaultValues()` 把 32 个主题项**全设成同一组前景/背景色**，
      彩屏上跑出来跟单色 GD-77 一模一样（实测整屏只有 2 种颜色），
      A3/A4 的分段着色、电池语义色全被压成黑。

      做法：`Options → Theme Options` 加一行 `Colour:Mono/Colour/Custom`。
      左右键切换并**立即预览**（切换页本身就是用这套颜色画的，预览即反馈），
      SK2+Green 存盘，Mono 随时退回。
      **不存「选了哪个」**，直接比对当前主题反推，所以手改过就老实显示 `Custom`。
      预设表全是 `const`，**RAM 零开销**。

      **只改前景色，这是设计决定**。三个背景项全是陷阱：
      - `BG_MENU_NAME` 填满了标题栏，但标题文字用 `THEME_ITEM_BG` 当背景画 →
        每个字符格会在彩色条上打一个背景色方块
      - `BG_HEADER_TEXT` 正常情况没有整条填充，只是表头文字的逐字符背景 →
        染了就是「字底深色块、字间露白」
      - `BG_MENU_ITEM_SELECTED` 是填充了，但选中行文字**反色**画，
        会把 `FG_MENU_ITEM` 当字底盖在填充上 → 要让选中行有色就得把菜单全部文字一起染

      剩下的地方颜色才承担含义：**红=发射与错误，琥珀=警告与 S5–S9 区段，
      绿=信号正常，蓝=身份，灰=次要**。这正是固件其他地方已按名字要的那几个主题项，
      所以**电池图标的绿/黄/红、S 表分区色不用改一行绘制代码就自动生效**。
      日间（白底）用深色、夜间（黑底）单独挑浅色，不是自动调亮。

      实机对比：Mono 整屏 2 色 → Colour 6 色，且每种都有含义
      （S 表绿 + S5 以上琥珀、电池绿且有外框、TX 那行红而 RX 保持黑）。

#### A4b 实测发现（用按键注入 + 抓屏自查出来的）
1. **`Batt icon:On` 原本画不出来** —— 它写成了 `else if` 链的第三个分支，而电池文字
   （`87%` / `7.4V`）和表头时钟共用右侧唯一那一格。只要时钟开着**或**电池显示成电压，
   图标就永远轮不到。这两项这台机器默认都是开的 → 选项开着但什么都不发生。
   改法：图标提到文字之前判定，**取代**两种文字；时钟占右格时图标移到
   功率与 GPS 之间那段 ~35px 空白（实测 x 72–106 空着）。
2. **GPS 图标和时钟重叠** —— 图标画在 x 130–137，右对齐的 `03:40` 占 130–158，
   而且图标画在时钟之后，会盖掉第一位数字。
   改法：图标**取代** "GPS" 三个字母（同一 x），省 10px，且把"加粗=已定位"
   这种没人看得出来的编码换成信号格：1 格搜星 / 2 格 2D / 3 格 3D。
   越界用 `_Static_assert` 钉死。
3. **改完第 1 条还是不显示** —— 同一类 bug 的第二只。图标脱离了 if/else 链，
   但它依赖的 `batteryPercentage` **只在「显示百分比」那条分支里才计算**；
   用户设的是 `Battery:V`，那个值一直是 -1，判断照样挂掉。
   改法：图标要用就自己调 `getBatteryPercentage()`。
   **教训：把一个东西从条件链里提出来时，它依赖的值也得一起提出来。**

**刷机后实测表头布局**（读帧缓冲量的列区间）：
`FM` 1-11 · `1W` 60-69 · **电池图标 84-103** · **GPS 信号格 108-109（蓝）** · 时钟 130-158。
四样东西各就各位、零重叠。电池填充是黑的而不是绿/黄/红 —— 那是 A6（默认主题纯黑白）。

常量级改动。**用远程屏幕自查，不再等实机反馈。**

- [x] B0 **修掉 host 侧的帧缓冲解码** —— 之前按「小端 + BGR565」解，两处都错。

- [x] B2 **调色板换掉** —— 原来是经典 jet 彩虹。彩虹是错的编码：RSSI 是量级，

      2m 底噪占 level 5–38、中位 19，正好被涂成满饱和青绿，
      真载波（level 63）淹在里面。

      对比图 `backup/waterfall-before-after.png`，

      因为屏幕上每个瀑布像素都能反查回 level，等于拿同一批真实数据走两套映射。

      **刷机后实测验收**（只统计真正画过的行，反查新调色板）：
      底噪 level 中位 **7/63**（11% 量程，改前 19）、95% 分位 14；

- [x] B4 **瀑布图 gamma 做成 UI Style 选项** —— `WF gamma: Linear / Square / Cube`

      用 `uiStyle_t` 里一直空着的 `reserved` 字节。**0 必须继续表示「平方」**：
      存量的 style 块那个字节是 0，而当时的行为就是平方律，改变 0 的含义会让
      已经保存过设置的人升级后显示无声变样。抽了 `uiStyleWaterfallContrastOf()`
      给「实时设置」和「菜单工作副本」共用，免得两处各有一套默认值的理解。

      **三档的对比是同一批 4480 个真实样本算出来的**（Linear 是恒等映射，所以实测

      | | 底噪中位 | 75% | 95% | 峰值 | 用到色阶 |

      | Linear | 8 (12%) | 24 | 32 | 46 | 73% |

      固件里一直有三条自动进 DFU 的路，`flash.py` 却只接了失败的那条：
      `0x9F`（改写初始 SP 字的有效位）**不行** —— 这颗 STM32 拒绝重编程一个已编程的字，
      而 HAL 照样返回 HAL_OK、错误码 0，字纹丝不动；
      `0x9D`（伪造 PTT+顶键跳 bootloader）实测**没回应、USB 也没重新枚举**，
      电台从总线上掉了（不留持久状态，断电即恢复）；
      **`0x9C`（擦除 app 首扇区再复位）1 秒就进了 DFU** —— `0x9F` 败在"不能改写已编程的字"，
      擦除正好绕开这个限制。`flash.py` 已改用 `0x9C`。
      它是**持久**的（擦了只能进 DFU 直到写回），所以只该紧挨刷机用，正好就是这个场景；
      不会变砖，扇区 0-2 是 bootloader，从不被碰。
      ACK 常收不到（复位只延后 500 ms），所以判据是 DFU 设备有没有出现，不是回应。

### D. 卫星增强
- [x] D1 **TLE 工具 `tools/sat.py`** —— 实机验收

      「星表扩充」原来的提法不对：星表是**码表里的 25 个固定槽位**
      （自定义数据类型 3，2520 字节，CPS 写入），槽位数改不了。
      真问题是 **TLE 会过期**：星历大约每老一周，过境预报就差一分钟，
      而电台既不知道自己的星历多旧、也从不说。

      TLE 在码表里是**半字节压缩**的：每字节两个 nibble 查表 `"0123456789. +-*"`，
      第一行 12 字节→24 字符，第二行 28 字节→56 字符。
      存的不是原始 TLE 文本，而是推演器要的那几个字段，按列直接拼接、无分隔符：
      - L1 = 标准 TLE 第一行的 `[18:20]`（年）+ `[20:32]`（历元日）+ `[33:43]`（M2）
      - L2 = 第二行的 `[8:16] [17:25] [26:33] [34:42] [43:51] [52:63] [63:68]` + 一个空格
      （这套列号是**拿电台里已存的数据反推并核对过的**，不是照文档猜的。）

      `sat.py list` 报每颗星的历元和已过去多少天；`refresh` 从 CelesTrak
      业余卫星组取新星历写回去（整扇区先备份，默认只预演，`--yes` 才写）。
      名字匹配用子串 + 别名表——AO-91 在 CelesTrak 里叫 `RADFXSAT (FOX-1B)`，
      PO-101 叫 `DIWATA-2B`，纯子串匹配会漏；**对不上的会报出来，不静默跳过**。

      1. `"%+d"` 作用在 `delta/1000` 上 —— 整数除法向零截断，把符号和量值一起扔了，

         违反了本项目自己的规矩：宁可报错也不悄悄吞掉。

      两个都不是看屏幕能发现的——截断前那张图有数字有正负号，看着完全合理。
      **是拿原始字节核对算术才露的馅。**

**订正：本节原来写的"要先腾 RAM"是错的。** 2026-09-22 实测了一遍，中文根本不吃 RAM：

| 资源 | 总量 | 已用 | 空闲 | 中文要占 |
|---|---|---|---|---|
| 主 RAM | 128 KB | 131008 B | **64 B** | **0** —— 字形解到已有的栈缓冲 `uncompressChar[64]` |
| CCM | 64 KB | 65468 B | **68 B** | **0** |
| 内部 flash·Pool A（`.rodata`，codec 之前的填充） | — | — | **95,476 B** | 语言表 4823 B/种 |
| 内部 flash·Pool B（codec 之后，要自建 linker section） | — | — | **188,056 B** | — |
| 外部 SPI flash | 16 MB | 校准 1 KB + 码表 + 末尾 2 MB 日志 | **十几 MB** | **字库放这儿** |

注意 `arm-none-eabi-size` 的 `text` 会把 `.codec_bin_section_1` 的**填充**算进去，
所以不能拿它减出空闲量。真实分界：`.rodata` 一路长到 `0x807537C`（codec 的
`ABSOLUTE` 地址）就会**链接失败**，这 95 KB 就是普通 `const` 的天花板。
一级字库 16×16 = 3755 字 × 32 B = **117 KB**，塞不进 Pool A —— 所以
BA7IQE 把字库放外部 flash 是对的，我们照做，而且我们比他宽裕（他要挤 GPS LOG，我们不用 GPS LOG）。

渲染层（`HX8353E_display.c`）的实际情况，比预想的好：

- **唯一入口** `displayPrintCoreDoubleHeight()`，全部文字都走它，改一个函数就够。
- **"字形不在字库数组里"的通路已经存在**：`fontIsCompressed` → `getUncompressedChar()`
  把 RLE8 解进栈上的 `uint8_t uncompressChar[64]`。16×16 点阵正好 32 B，
  **从 SPI flash 取字形复用这同一个缓冲，零新增 RAM。**
- **`FONT_SIZE_3` 是 8×16** —— 16×16 汉字与它**等高、正好双宽**，中英混排天然对齐。
- 真正要改的是 **x 推进**：现在是 `i * charWidthPixels` 定宽，居中/右对齐和越界截断
  `(charWidthPixels * sLen) + xPos > DISPLAY_SIZE_X` 全按定宽算，双宽字必须改成游标累加。
- 点阵是**列优先**（`currentCharData[x + (y/8)*charWidthPixels]`），标准 HZK16 是行优先，
  要转置 —— 离线转一次，不是运行时开销。

语言包：`const char XXX[LANGUAGE_TEXTS_LENGTH]` **定长 17 字节** × 284 条；
符号表里 `languages` 是 `R`（只读段 = flash）、两种语言共 9646 B，**不进 RAM**。
槽位只有 2 个（English + 1），中文顶掉副语言即可，净增 ≈ 0。
17 B 装 UTF-8 汉字只有 5 字，双字节编码 8 字；不够就把 17 加宽，每加 1 B 成本 568 B。

**最大的工作量不是字库也不是渲染，是版面**：160 px ÷ 16 px = **一行只剩 10 个汉字**，
现有 UI 全按 20 个 8px 字符排。BA7IQE 干了两周，大头应该在这。

## 控制端版面

原来是 `1fr + 330px` 两栏，右栏堆了 8 张卡。实测**右栏 3157px、左栏 993px**、整页 3291px ——
330px 宽的一栏扛着全部次要功能，旁边 796px 的地方大半是空的。

重排成两层：

- **上层**两块操作台并排：码表（信道 + 修改信道）| 电台屏幕加键盘。
  屏幕栏只在视口 ≥980px 时 sticky —— 那张卡约 840px 高，
  **比视口还高的 sticky 元素会把自己的下半截藏起来**。
- **下层**一个通栏 `repeat(auto-fit, minmax(318px,1fr))` 网格装其余七张卡，
  **按高度降序排**（普通 grid 行高取该行最高者，降序能少留空洞）。
- 频段日志控件搬进热力图卡，**控件跟它的输出放一起**。
  卡片默认窄，JS 在有数据时才 `classList.add("full")` 加宽。
  **常驻两列是错的**：空卡只有 206px，旁边 468px 的卡会挖出 262px 的洞，
  实测整页反而从 1947 涨到 2331px。
- 「做不到的事」改成默认折叠的 `<details>` 通栏条 —— 说明文字不该占控件的位置。

结果 **3291 → 1947px，最高列 3157 → 987px**。
断点实测 1180/1000/820/420 → 3/2/2/1 列。
改完导出 43 轮日志验过：热力图照常渲染、卡片按预期加宽到 1144px。

## 绿灯与静噪：一次追到底的记录

**症状**：绿灯常亮、S 表空、界面像卡住、按键唤醒几秒又卡。

**第一层（已解决）**：卡住是上游省电模式 `ecoLevel`（出厂默认 1）。它只关射频不关屏，
`Options → General Options → Eco Level` 改 0 即止。

**第二层：绿灯没有主人**（`ENABLE_LED_OWNER`）

29 处 `LedWrite(LED_GREEN, ...)` 分散在 10 个文件，全是**边沿写入**，没有任何地方
周期性重新求值。任一转换被跳过，灯就永远错下去。上游自己的两处补丁是证据：
`trx.c:592` 的 `|| LedRead(LED_GREEN)`（**把 LED 硬件当状态变量读回来**）和
`uiVFOMode.c:4727` 的注释 *"trxCheck*Squelch() won't be called while sweeping,
blindly turn the green and red LED off"*。
修法是补上缺失的**电平驱动主人**（`Leds.c` 的 `ledsTick()`），29 处边沿写入一处不动，
错误上界从「永远」降到「一个 tick」。代价 4 字节 `.bss`。

**第三层：两处 ECO 时序缺陷**

- `ENABLE_ECO_SQUELCH_FIX` —— `trxReadRSSIAndNoise()` 拒绝在射频关断时采样，
  但 `trxCheckAnalogSquelch()` 自己的 25 ms 定时器照常到期，**在 120 ms 断电窗口里
  用最多一整窗旧的数据判断四次**，而它的「开」分支会点灯并开音频。
- `ENABLE_ECO_WAKE_SETTLE` —— ECO 有两条上电路径，**只有周期性唤醒调了
  `trxPostponeReadRSSIAndNoise()`**，事件唤醒（按键/信号/USB）没调。

**关键实测数据**（来自我们自己的 `scanreject.h`，2026-07-28 台架）：

> AT1846S 的噪声字节（0x1B 低字节）**在接收机重启时被复位到 127**，
> 需要 **10–15 ms 才降到有意义的范围**；RSSI 约 2.5 ms 可用。

推论：**ECO 每 240 ms 重启一次接收机**（level 1），噪声值每轮都从 127 重新下降、
只有 25 ms 可降 —— 所以开着 ECO 时采到的噪声**系统性偏高**。
偏高只会让静噪更难打开，**不会误开**。这条实测数据直接否掉了「唤醒瞬间误判有信号」
这个假设，也给「开省电就收不到消息」提供了量化依据。

**静噪门限**：`squelch = 70 − (sql−1)×3`，默认 `sql=10` → **开于噪声<43，关于>46**。
噪声字节是 SNR 性质的，所以**弱而干净的信号会开静噪但几乎不动 S 表** ——
「灯亮 + S 表空」本身并不矛盾。

**方法论教训**：我在这条上连猜错三次（CPS 屏、USB 抑制、唤醒误判），
每次都是在没有数值的情况下硬推。正确顺序是**先数写入点、先查已有实测记录**，
这两件事加起来不到二十分钟，却比几小时的推理都管用。

## 规矩

- 每个功能一个编译开关，默认关闭，**关闭时行为与 stock 等价；二进制若有差异必须能解释**
  （例：`codeplug.h` 的枚举是共享定义，加新类型必然改变 stock 的代码生成，差 4 字节，已查明无副作用——
   自定义数据区是链表式按类型匹配，不是按枚举索引布局，已有数据不会被挪动）
- **电台自报的「编译于」不可信** —— 那个时间戳来自 `__DATE__`/`__TIME__`，
  编进 `usb_com.c`；增量构建时它没被重编，报的就是**上一次**的时间。
  要确认电台上跑的是哪个固件，用 `python tools/flash.py <某个.bin> --verify`：
  从 MCU ROM 回读 5 处 x 2048 字节跟本地合并结果比，0.4 秒，能区分相邻两版。
- **换编译开关必须 `rm -rf build`** —— `make` 不跟踪开关变化，只看源文件时间戳。
  不清就换开关会得到**混合构建**（部分 .o 还带着上一轮的开关），
  我就这么撞上过一次「莫名其妙的 104 字节 RAM 溢出」，其实是残留的 AES 目标文件。
- **先让状态可观测，再动手调。** D2 那一轮我花了几个小时从屏幕反推 RAM 里的
  `alarmType`/`alarmTime`/`dateTimeSecs`，推错两次（`isVisible` 的语义、时钟被我自己改坏），
  还把电台时钟弄错 33 分钟。加一条只读诊断命令（CPS `0x98`）之后几分钟就定位了。
  **远程抓屏读的是帧缓冲，而彩屏平台上 `uiNotificationRefresh()` 推完屏会立刻把帧缓冲还原
  —— 所以抓屏结构性看不见任何通知。** 涉及通知的功能不能用抓屏验证。
- **验证手段不该比被验证的东西更难观测**，也不该扰动被测对象：
  用 CPS 改时钟做加速测试时，`usb_com.c` 会顺手调 `menuSatelliteScreenClearPredictions()`
  把闹钟清掉——测试动作本身杀死了被测对象。进卫星屏还会切 CPU 到 HS_RUN，USB 会断开重枚举。
- **该主动给出止损点。** 做不出来的东西要自己喊停，而不是等用户喊。
- **「像死机」先怀疑设置，再怀疑代码。** 2026-09-21 实机：屏幕不刷新、绿灯常亮、S 表不动、
  按一下键活几秒又卡住 —— 真相是上游的省电模式 `ecoLevel`（出厂默认 1）。
  它**只关射频芯片、不碰屏幕和背光**，而绿灯/S 表都由 RSSI 驱动，
  射频断电后 `LedWrite(LED_GREEN, 0)` 走不到，灯就停在亮着。
  `Options → General Options → Eco Level` 改 0 即止。
  **我在这条上连猜错两次**（先赖 CPS 屏没退出、又赖 USB 抑制），
  两次都是在没有数据的情况下硬推，还把用户没说过的话当成了前提。
  正确做法是**第一时间给一个用户能自己一次性证伪的判据**，而不是继续讲机制。
- 改完四种配置都要能编：stock / WATERFALL / WATERFALL+FAST_SCAN / 全功能。
  **别拿 `size` 的 text 当判据** —— 四种配置编出来 text 全是 728864，我一度以为回归脚本坏了。
  真相：`.codec_bin_section_1`（AMBE 占位）被链接脚本钉在固定结束地址，
  `.text` 长一点它就短一点，两者之和恒定。代码变没变看 **md5**，装不装得下看 **RAM**。
  （我一度以为占位段起始地址随代码大小浮动 —— **是我看错了**。链接脚本里写的是
   `. = ABSOLUTE(0x807537C)`，地址钉死；`size -A` 报的是补齐**之前**的段起点，
   段长里也把 padding 算进去了，所以看着像在动。
   拼接偏移就是固定的 0x6937C = 0x807537C − 0x800C000，长度 0x48BB0，
   上游 `opengd77_stm32_firmware_loader.py` 写死这两个常量是对的。）
- `ENABLE_KEY_INJECTION` 和 `ENABLE_AES + ENABLE_DMR_DATA` **装不下**：一起开
  RAM 溢出 104 字节。按键注入是 dev 开关，自查 UI 时单开，日常固件不带。
- 越界风险用 `_Static_assert` 在编译期挡住
- 历史固件留在 `firmware/out/`，随时可退
